# 数据源治理记录：温州市公共数据开放平台 `cata_12720`

> 本文只记录数据来源、字段口径、访问状态与校验值存放位置，不记录任何凭据取值。
> 本系统仅用于教学科研与辅助分析，不替代水行政主管部门的正式监测、预警、调度或应急决策。

## 2. 接口与字段

接口基础路径：`https://data.wenzhou.gov.cn/jdop_front/interfaces/cata_12720`

| 路径 | 用途 |
| --- | --- |
| `/get_total.do` | 返回平台声明的记录总数 |
| `/get_data.do` | 分页返回数据记录，参数 `pageNum`、`pageSize` |
| `/get_dataupdate_date.do` | 返回平台数据更新日期 |

字段字典（沿用平台官方字段名，本仓库不做重命名）：

| 字段 | 含义 | 下游处理 |
| --- | --- | --- |
| `time_d` | 观测时间（平台原始时间文本） | 由 `normalize_water_level_rows` 解析并本地化到 `Asia/Shanghai`；不可解析、歧义或不存在的本地时间记为 `invalid_timestamp_rows` |
| `up_water_level` | 水位值（源字段名称为“实时水位”） | 转 `float64`；缺失记 `missing_level_rows`，非有限值记 `invalid_level_rows` |
| `z_id` | 记录标识 | 转字符串后作为 `source_record_id`；重复者保留最后一次出现并记 `duplicate_rows`；缺失或不可用记入 `invalid_timestamp_rows` |

口径警示：源字段名称中的“实时水位”**只是字段名称**，不代表平台向本系统持续实时推送。任何历史数据演示都必须标注“历史回放 / 离线数据”。

## 3. 分页与配额

- 单页上限：`200`（`MAX_PAGE_SIZE`），超过即由适配器拒绝，不做静默截断式请求。
- 迭代规则：按 `get_total.do` 声明的总数分页取数；单页返回超过剩余数量时截断，绝不产出超过平台声明数量的记录。
- 空页提前结束迭代。

## 4. 访问审批状态

- 当前状态：**`API_AUTH_PENDING`**——接口凭据（`WENZHOU_DATA_APPSECRET`）尚未获批/未提供，本仓库未持有真实凭据。
- 凭据只通过环境变量提供，**不写入任何文件、产物、日志或异常消息**；产物中对凭据形态做了兜底脱敏。
- 状态未变更为已授权之前：不得声称使用了真实接口数据，不得把样例或合成数据表述为实测数据。

## 5. 获取时间与校验值的存放位置

每次取数都会写不可变原始快照与相邻清单（快照写在当次运行的 run 目录内，run 目录自包含）：

- 快照：`<run 目录>/wenzhou/<dataset_id>/YYYY/MM/DD/<UTC时间戳>-<sha256前12位>.ndjson`
- 清单：同目录同名 `.manifest.json`，含 `source_name`、`source_uri`、`dataset_id`、`acquired_at`（获取时间，UTC）、`request_parameters`、`record_count`、`sha256`
- 快照为合法 JSON（NDJSON，非有限数值写 `null`），校验值即清单中的 `sha256`，可用 `sha256sum`/`Get-FileHash` 复核。
- 快照写入使用排他创建：已存在的快照绝不被覆盖；run 目录名唯一（时间戳 + 同秒序号），因此快照路径唯一、同一批数据重复运行不会撞名。
- 每次运行保留当次抓取的原始快照，**不做跨 run 去重**；长期运行需自行清理旧 run 目录。

## 6. 更新频率警示

- 平台的实际更新频率以 `/get_dataupdate_date.do` 返回为准，本仓库不做假设。
- 重跑管线时必须重新记录获取时间与快照 SHA-256；不同批次的结论不得混用。

## 7. 本地样例

- `data/samples/water_level_sample.csv` 是**合成演示数据**，数值由本项目按小时序列人为构造，不是真实观测值。
- 该样例刻意保留三类质量缺陷（1 个重复 `z_id`、1 个缺失水位、1 个非法时间戳），仅用于自动化测试与管线演示。
