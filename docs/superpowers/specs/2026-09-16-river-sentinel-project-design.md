# 河道水位预测与防汛决策智能体项目设计规格

## 1. 项目定位

- 中文名称：河道水位预测与防汛决策智能体
- 英文代号：River Sentinel
- 项目类型：浙江水利水电学院人工智能专业本科毕业设计，同时复用成果完成相关课程实训
- 首期研究范围：温州市公开水雨情数据、5～20 个代表性河道站、未来 1/3/6 小时水位预测
- 可扩展范围：通过配置更换地区、数据源、监测站集合和预测时域

本项目使用真实公开水雨情数据，构建数据治理、模型训练、水位预测、风险预警、防汛决策智能体和可视化系统的完整闭环。系统定位为教学科研和辅助分析工具，不替代水行政主管部门的正式监测、预警或调度决策。

## 2. 建设目标

1. 建立具有数据来源记录、质量检查和时间对齐能力的水雨情数据流水线。
2. 建立持久性基线、机器学习模型和深度学习模型的可复现实验体系。
3. 预测代表性河道站未来 1、3、6 小时水位，并评估超警事件识别能力和提前量。
4. 建立确定性风险规则引擎，将模型预测与站点警戒水位等业务规则结合。
5. 建立能够调用数据查询、预测、预警、知识检索和简报工具的防汛决策智能体。
6. 建立包含地图、曲线、预测、预警、智能问答和简报的完整业务系统。
7. 按浙江水利水电学院毕业设计流程持续沉淀选题、开题、过程检查、实验、论文、答辩和归档材料。

## 3. 技术方案

### 3.1 技术栈

- 后端：Python、FastAPI、Pydantic、SQLAlchemy
- 智能体：LangGraph，结合工具调用和检索增强生成
- 算法：Scikit-learn、XGBoost 或 LightGBM、PyTorch
- 数据库：开发期 SQLite，部署期 PostgreSQL
- 缓存与任务状态：Redis
- 前端：Vue 3、TypeScript、Vite、ECharts
- 部署：Docker Compose
- 测试：Pytest、Vitest 和前端类型检查
- 自动化：GitHub Actions

### 3.2 模型研究范围

模型研究至少包含三层对比：

1. 基线模型：当前水位持久性预测、历史统计基线；
2. 机器学习模型：XGBoost 或 LightGBM；
3. 深度学习模型：LSTM 或 TCN。

训练、验证和测试数据按时间顺序切分，禁止随机切分导致未来信息泄漏。实验至少记录数据时间范围、站点集合、特征、参数、随机种子、代码版本和运行环境。

评价指标包括 MAE、RMSE、R²、NSE，以及超警事件的准确率、召回率、F1 和预警提前量。最终论文必须同时报告平均预测性能和重点洪水过程表现，不只展示最优实验。

### 3.3 智能体边界

智能体负责理解用户意图、编排工具、检索防汛知识、解释结果和生成简报。风险等级必须由预测服务与确定性规则引擎产生，大语言模型不得自行决定风险等级或伪造监测数据。

智能体工具至少包括：

- 实时或最近水雨情查询；
- 历史过程查询与统计；
- 水位预测；
- 预警规则查询与风险判定；
- 图表与水情简报生成；
- 防汛知识库检索。

每次回答保留数据时间、模型版本、工具调用摘要和依据。缺少数据或模型不可用时明确降级，不把陈旧数据标记为实时数据。

## 4. 系统架构

```text
浙江水雨情及公共开放数据
        ↓
原始数据归档与来源登记
        ↓
清洗、质量检查、缺失处理、时间对齐
        ↓
特征工程与时间顺序数据集切分
        ↓
基线/机器学习/深度学习训练与评估
        ↓
模型版本产物与预测服务
        ↓
确定性预警规则引擎
        ↓
LangGraph 防汛决策智能体
        ↓
Vue 地图、曲线、预警、问答与简报
```

各模块通过明确接口隔离：算法模块负责训练与推理契约，后端负责业务编排和持久化，智能体仅通过工具访问业务能力，前端只访问后端 API。

## 6. 毕业设计过程材料

`docs/graduation` 按学校过程管理需要划分为：

1. `01-topic-approval`：选题审批；
2. `02-task-book`：任务书；
3. `03-proposal`：开题报告；
4. `04-literature-review`：国内外研究现状和文献综述；
5. `05-foreign-translation`：外文文献与翻译；
6. `06-progress-records`：指导记录与阶段成果；
7. `07-midterm-check`：中期检查；
8. `08-acceptance`：系统验收、测试报告和用户手册；
9. `09-thesis`：正式论文；
10. `10-defense`：答辩 PPT、演示脚本和问题库；

论文模板、正文字数、查重阈值和当届时间节点以计算机科学与技术学院及指导教师最新通知为准，不在工程配置中写死。

## 7. 阶段工作流

### 阶段 0：选题审批

形成选题背景、应用价值、工作量、预期成果和审批材料。

### 阶段 1：开题准备

形成任务书、开题报告、文献综述、技术路线、进度计划和外文文献选择记录。

### 阶段 2：数据基线

形成数据来源记录、数据字典、原始数据校验信息、清洗规则、探索性分析和基线预测结果。

### 阶段 3：模型研究

完成基线、机器学习和深度学习模型，形成可复现实验配置、指标表格、图像、误差分析和典型事件分析。

### 阶段 4：系统实现

完成预测 API、风险规则、智能体、可视化系统、自动简报、测试和用户手册。

### 阶段 5：论文与答辩

完成中期与末期材料、作品验收、论文、答辩材料和最终归档。

每个阶段都必须先定义验收标准，再实施、审查、验证和提交。实验结论只有在原始结果、配置和代码能够对应时才能写入论文。

## 8. Codex 协作角色

- `project_explorer`：只读定位代码、接口、数据流和影响范围；
- `data_auditor`：只读检查数据来源、许可、质量、异常、时间对齐和数据泄漏；
- `ml_reviewer`：只读检查模型选择、基线、指标、实验设计、可复现性和结论证据；
- `code_reviewer`：只读检查正确性、安全性、异常处理、回归风险和测试缺口。

主 Agent 负责需求分析、方案设计、任务拆分、实现协调、实际 diff 检查、验证与 Git 管理。只读 Agent 不修改文件，不以聊天摘要替代实际代码和实验记录。

## 9. Git 工作流

仓库默认分支为 `main`。较大阶段使用独立功能分支和 worktree，例如：

- `docs/topic-and-proposal`
- `data/ingestion-pipeline`
- `ml/baseline-models`
- `ml/deep-learning`
- `backend/prediction-api`
- `backend/flood-agent`
- `frontend/monitor-dashboard`
- `docs/thesis-and-defense`

功能完成后依次执行任务报告、实际 diff 检查、专项只读审查、测试或实验验证、中文提交、合并到 `main` 后再次验证。未经用户明确确认不推送远程仓库。

## 10. 异常处理与安全

- API 使用统一错误响应并记录可追踪请求标识；
- 数据源失败时保留最近成功快照并显著显示数据时间；
- 生产预测模型不可用时允许回退到已验证基线模型并记录原因；
- 智能体工具失败时返回明确失败状态，不生成替代数值；
- 所有外部输入执行格式和范围校验；
- `.env`、口令、Token、数据库备份、真实大数据和模型权重禁止提交；
- 不使用真实个人信息；
- 页面和报告显示“教学科研辅助，不替代官方防汛决策”。

## 11. 测试与验证

- 后端：健康检查、配置加载、API 契约、业务服务、规则引擎和智能体工具测试；
- 前端：类型检查、组件测试、关键交互测试和生产构建；
- 算法：预处理、特征、时间切分、指标、训练烟雾测试和推理契约测试；
- 数据：字段、时间范围、重复、缺失、异常和来源一致性检查；
- 集成：从样例数据到预测、风险判定、智能体回答和前端展示的最小闭环；
- 论文：指标表格可由实验产物生成，典型图表可以追溯到配置和数据快照。

CI 至少执行后端测试、算法测试、前端类型检查、前端测试和前端构建。大规模训练不放入常规 CI，使用小型公开样例完成烟雾验证。

## 12. 初始化交付与验收

首轮初始化交付：

1. Git 仓库和 `main` 分支；
2. 根目录协作规则与四个只读 Agent 配置；
3. 模块化目录和基础配置；
4. FastAPI 最小服务及健康检查；
5. Vue 3 最小可运行页面；
6. 算法模块配置与流水线边界；
7. Docker Compose 基础配置；
8. 数据来源、数据字典和实验记录模板；
9. 需求、开题、论文、进度和答辩基础文档；
10. 基础测试与 CI；
11. 实施计划和可复现启动说明。

验收条件：后端测试通过、前端类型检查和构建通过、算法基础测试通过、Docker Compose 配置检查通过、文档覆盖学校主要过程材料、仓库不含敏感或虚假内容、最终工作区干净。

## 13. 非目标

首轮初始化不下载大规模真实数据、不训练正式模型、不声称达到任何预测精度、不实现真实防汛调度、不接入生产预警渠道，也不以智能体输出替代官方结论。上述能力必须在后续阶段基于真实数据、评审和验证逐项建设。
