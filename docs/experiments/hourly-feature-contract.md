# 小时特征矩阵契约（DS-4b）

本文冻结 `ml/src/river_sentinel_ml/features.py` 的输出列语义与泄漏边界，供 DS-5b（小时基线）
与 DS-6（模型）直接引用。所有内容均可用 `scripts/build_hourly_features.py` 的产物与
`ml/tests/test_features.py` 复现。

**使用声明**：本数据集、本特征矩阵与后续一切结论仅用于教学、科研与辅助分析，
不替代水行政主管部门的正式监测、预警、调度或应急决策，不得冒充官方发布预警。

## 1. 输入与产物

| 角色 | 路径 | 实测 |
| --- | --- | --- |
| 水位小时表（DS-2b） | `data/processed/water_level_hourly_cata12720.csv` | 3090 行、SHA-256 `9901D4CC…FB1A8`、`max_interpolation_steps=2` |

两份输入都是**历史数据 / 历史回放**，不是实时推送数据。

## 2. 列契约（顺序固定，不得调整）

| 序号 | 列名 | 语义 |
| --- | --- | --- |
| 1 | `observed_at` | 桶左沿时刻，`datetime64[ns, Asia/Shanghai]`，ISO 8601 含 `+08:00` |
| 2 | `segment` | `train` / `validation` / `test` |
| 3 | `water_level_t` | `t` 时刻水位；插补值保留可见（缺失时为 `NaN`） |
| 4–9 | `water_level_lag_{1,2,3,6,12,24}` | `t − k` 时刻水位 |
| 10–15 | `rain_lag_{0,1,2,3,6,12}` | `t − k` 时刻区域平均降雨；`rain_lag_0` 即 `t` 时刻 |
| 16–20 | `rain_cum_{1,3,6,12,24}` | `t − w + 1 … t`（含两端）的降雨之和；窗口不完整时为 `NaN` |
| 21–22 | `hour_of_day`、`month` | 由 `t` 的本地时间派生；**不生成**汛期标志（无官方口径依据） |
| 23–25 | `target_h{1,3,6}` | `t + h` 时刻水位，仅在本段内取值 |
| 26–28 | `usable_h{1,3,6}` | 该行能否作为 horizon `h` 的有标签样本（见 §4） |
| 29 | `is_imputed_t` | `t` 时刻是否被插补 |
| 30 | `source_record_id_t` | `t` 时刻的记录主键（可追溯） |
| 31 | `rain_point_count` | `t` 时刻参与等权平均的降雨网格点数（本数据集恒为 5） |

`feature_columns()` 返回交给模型的特征列，共 20 列：`water_level_t`、6 个水位滞后、
6 个降雨滞后、5 个降雨累计、`hour_of_day`、`month`。键、`segment`、`target_h*`、
`usable_h*` 与三个溯源列一律排除。

## 3. 泄漏边界

1. **严格因果（HS-D-8）**：任何特征列只依赖 `≤ t` 的信息。不存在未来水位、未来降雨、
   全数据集归一化或插补统计量。已固化为测试探针：把降雨表中 `t` 之后的观测整体置为
   `NaN`，`≤ t` 各行的 `rain_lag_{k}` 与 `rain_cum_{w}` 逐元素不变。
2. **不跨段（HS-D-7）**：先按 `split_ratios` 对**完整**小时网格做时间顺序切分（整数边界，
   与 `dataset.chronological_split` 同口径，测试逐行比对），再在**每段内部**独立计算滞后、
   累计窗口与标签。段首的滞后/累计为 `NaN`，**不借用**上一段末尾值。
3. **标签不跨段**：每段末尾 `h` 行的 `target_h{h}` 为 `NaN`，避免训练段使用验证/测试期的水位。
4. **删除未来行不改变过去**：截断水位表的尾部后重算，仍在 `train` 段内的前缀逐元素不变。
5. **测试段不影响训练段**：改写 `test` 段的水位取值后，`train` 与 `validation` 段的所有列
   逐元素不变。
6. **插补不隐藏（C-5）**：`water_level_t` 与滞后列保留插补值以便追溯，但目标时刻被插补的
   样本 `usable_h{h}=False`。

以上第 1–5 条都在 `ml/tests/test_features.py` 中以测试用例形式固化，不是报告结论。

## 4. `usable_h{h}` 的口径

一行只有在**三条同时成立**时才算 horizon `h` 的可用样本：

1. 目标小时（`t + h`）落在同一段内且水位非缺失；
2. 本行 `water_level_t` 非缺失（否则 DS-5b 的持久性基线拿不到锚点）；
3. 目标时刻 `is_imputed = False`（C-5）。

第 2 条与 DS-2b「`t` 与 `t+h` 均为有限值」的样本口径一致；第 3 条是 DS-4b 额外扣掉的插补影响。
训练与评估都必须只使用 `usable_h{h} = True` 的行。

### 5.1 与 DS-2b 对照（逐级差额）

| horizon | DS-2b 全局口径 | 本实现重算 | 扣掉插补目标 | 再要求目标同段 | 实测 `usable` |
| --- | --- | --- | --- | --- | --- |
| h1 | 1955 | 1955 | 1952 | 1951 | **1951** |
| h3 | 1807 | 1807 | 1804 | 1801 | **1801** |
| h6 | 1613 | 1613 | 1611 | 1606 | **1606** |

- 3 个插补行（`2022-06-10T23:00`、`2022-06-11T00:00`、`2022-06-11T02:00`）全部落在 `train` 段；
  因此 `validation` 与 `test` 的可用样本量与 DS-2b 逐段口径**完全相同**，差额只出现在 `train` 段。
- 每段末尾 `h` 行因「标签不跨段」退出，故再减 1 / 3 / 5。
- DS-2b 的逐段口径（`t` 与 `t+h` 均有限、段内计算）是 1954 / 1804 / 1608，减去插补影响
  （−3 / −3 / −2）即得本实现的 1951 / 1801 / 1606。

## 6. 降雨口径（HS-D-9）

- 数据为 **Open-Meteo Best Match 网格化再分析降雨**；
- 5 个网格点（`WC-G1`…`WC-G5`）**等权平均**是「文成县区域降雨代理变量」；
- 它属于**历史再分析网格数据**：不是水文测站的仪器观测值，也不包含任何面向未来的
  气象信息。论文、页面、智能体回答与变量命名一律按本口径表述，不得改称其它来源；
- 主字段取 `rain_mm`；`precipitation_mm` 仅用于交叉核对：原始行差异 1268 行，与 DS-3 实测一致
  （小时区域平均后差异 552 行，因平均抵消了部分单点差异）；
- 本数据集对应时段（2022-06-02 ~ 2022-10-09，3090 小时）**全部**有降雨，缺失小时 0，
  `rain_point_count` 恒为 5。

## 7. 限制与风险（必须随结论引用）

1. **有界前瞻（HS-D-5）**：水位桶取**桶内末次观测**、时间戳取桶左沿，行 `t` 可能包含 `t` 之后
   最多 1 小时的读数。1 小时 horizon 的评估结果**偏乐观**，3/6 小时不受影响。本条不得被描述为
   严格因果序列之外的任何结论。
2. **test 段限制**：测试段 464 小时中 307 小时缺失（66.16%），`usable_h6` 仅 84 个样本。
   测试段指标只能作为探索性参考，不得据此给出确定性结论，也不得用于任何超参或特征选择。
3. **样本量**：全量可用样本 1951 / 1801 / 1606；`validation` 463 小时中缺失 250，
   `usable_h6` 仅 121。深度学习模型必须早停并严格使用验证集，结论保持保守（HS-D-12）。
4. **缺失与插补**：1061 个空缺桶不参与训练与评估；插补行数 3（阈值 2），保留可见但不作标签。
5. **代表性**：目标断面坐标未核实，降雨为县域区域代理变量，断面代表性有限。
6. **停止条件（HS-D-15）需主 Agent 裁定**：HS-D-15 规定「有效小时样本 < 1500 或**测试段有效小时 < 200**」
   即停止建模。全量可用样本 1606 ~ 1951 满足前者，但测试段 464 小时中有 307 小时缺失，
   实际有观测的小时仅 **157**（< 200），`usable_h6` 仅 84。DS-4b 只交付数据与口径，
   是否按 HS-D-15 判定「数据不足」、以及是否把测试段门槛改为按 horizon 的 `usable_h{h}`
   判定，属主 Agent 的裁定范围，本文不下结论。在裁定前，任何测试段指标都必须标注为
   探索性，不得用于模型选择。
